# presentacion

Usa este skill para crear presentaciones claras, ejecutivas y visualmente cuidadas a partir de una idea, tema, brief, documento o material base.

No uses este skill para:

- Documentos largos.
- Correos.
- Posts o piezas de copy independientes.
- Reportes extensos que no vayan a convertirse en slides.

## Flujo de trabajo

1. Si el usuario solo da un tema o una idea general, primero propone la estructura antes de construir la presentacion.
2. La estructura debe ser una lista de slides con:
   - Numero de slide.
   - Titulo propuesto.
   - Que va en la slide.
   - Que iria en notas del orador, si aplica.
3. Despues de proponer la estructura, espera el OK del usuario antes de construir la presentacion.
4. Si el usuario entrega un documento, brief o contenido base con suficiente detalle, puedes proponer una estructura ajustada al material y pedir confirmacion antes de generar el deck final.

## Reglas de contenido

- Una sola idea por slide.
- Usa titulares que afirmen algo.
- Evita titulos genericos como "Introduccion", "Contexto" o "Conclusiones".
- Prefiere titulos tipo:
  - "El problema cuesta tiempo, dinero y foco al equipo".
  - "La oportunidad esta en automatizar lo repetitivo sin perder criterio humano".
  - "El siguiente paso es validar con usuarios reales antes de escalar".
- Maximo 10 slides por defecto, salvo que el usuario pida otra cantidad.
- Usa poco texto visible por slide.
- Mueve la informacion de soporte, explicaciones largas, contexto adicional y guion a las notas del orador.
- Prioriza claridad, narrativa y toma de decision sobre decorar o llenar slides.

## Estructura obligatoria

Toda presentacion debe incluir:

- Slide de apertura con gancho: una frase fuerte, dato, tension, pregunta o insight que conecte con el problema.
- Slides de desarrollo con progresion logica: problema, oportunidad, propuesta, evidencia, plan o decision.
- Slide de cierre con una reflexion accionable.

El cierre por defecto debe invitar a responder:

"Que decision tomamos ahora y cual es el siguiente paso mas pequeno para avanzar?"

Puedes adaptar esa pregunta al contexto, manteniendo la idea de reflexion + accion concreta.

## Estilo visual por defecto

Usa un estilo minimalista tech:

- Fondo limpio, preferiblemente blanco, gris muy claro o negro suave segun el tono del tema.
- Paleta sobria con 1 color de acento.
- Colores sugeridos:
  - Base clara: blanco, gris claro, grafito.
  - Acento: azul electrico, violeta profundo o verde tech.
- Tipografia moderna sans serif, como Inter, IBM Plex Sans, Helvetica Neue, Arial o equivalente disponible.
- Mucho espacio en blanco.
- Jerarquia visual clara: titulo fuerte, soporte breve, visual principal.
- Usa iconos simples, diagramas limpios, capturas, mockups o imagenes conceptuales cuando ayuden a entender.
- Evita slides saturadas, fondos decorativos pesados, exceso de gradientes y bloques largos de texto.

## Imagenes y visuales

- Usa imagenes solo si aportan claridad, contexto o emocion.
- Para temas de tecnologia, producto o gestion, prefiere:
  - Diagramas de flujo simples.
  - Matrices.
  - Roadmaps.
  - Capturas o mockups.
  - Iconografia lineal.
- No uses imagenes genericas de stock si no aportan nada.
- Si un dato, proceso o comparacion puede entenderse mejor visualmente, conviertelo en grafico, tabla o diagrama.

## Entrega

Entrega la presentacion en ambos formatos cuando sea posible:

- Artifact para revisar visualmente.
- Archivo `.pptx` editable.

Si una de las dos formas no esta disponible en el entorno, entrega la alternativa posible y explica brevemente la limitacion.

## Criterios de calidad

Antes de entregar, revisa que:

- Cada slide tenga una sola idea central.
- Los titulos sean afirmaciones, no etiquetas genericas.
- El deck no supere 10 slides salvo instruccion distinta.
- Las slides tengan poco texto visible.
- Las notas del orador contengan el detalle que no cabe en la slide.
- La apertura tenga un gancho claro.
- El cierre deje una reflexion accionable.
- El estilo visual sea consistente y minimalista tech.
